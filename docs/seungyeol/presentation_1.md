# 1차 발표: 기획 + Meerkit

> 청중: 강사님, 운영팀 매니저, 부트캠프 수강생
> 기준 시간: **약 12분** (발표 10분 + 질문 2분). 시간이 다르면 맨 아래 "시간 조절"을 보세요.
> 슬라이드는 12장. 데모는 라이브 대신 **미리 연습한 경로 + 녹화본 예비**를 권장합니다.

## 0. 이 발표가 전달할 한 문장

> **"AI 서비스를 만들 때마다 처음부터 만드는 가입·로그인·권한 관리를, 설정 한 파일로 가져다 쓰는 스타터킷을 만들었다."**


## 0-1. 청중별로 노릴 것

| 청중 | 궁금한 것 | 이 발표에서 보여 줄 것 |
| --- | --- | --- |
| 강사님 | 기술 선택의 이유, 설계 근거 | 슬라이드 6~8 (기획 과정, 구조, 설계 결정) |
| 운영팀 매니저 | 범위, 진행 상황, 일정, 실현 가능성 | 슬라이드 5, 11, 12 (범위, 현황, 2차 예고) |
| 수강생 | "나도 쓸 수 있나?", 눈에 보이는 결과물 | 슬라이드 9~10 (데모, 문서) |

## 0-2. 먼저 정해 둘 말하기 원칙 (정직성)

- **백엔드는 아직 구현 전**입니다. 화면(UI)과 문서는 완성, 서버 연동은 다음 단계라고 **먼저 말하세요.** 질문받고 나서 인정하는 것보다 신뢰를 지킵니다.
- `npx create-meerkit`, `npx meerkit setup` 같은 **한 줄 세팅은 "계획"**입니다. "된다"가 아니라 "2차에서 보여 드린다"로 말하세요.
- 로그인 잠금은 브라우저 쪽 안내용이라 **서버에서도 막아야** 합니다. "보안이 끝났다"고 하지 말고 "서버가 해야 할 일을 문서에 명시했다"고 말하세요.

## 슬라이드별 구성안과 대본

### 슬라이드 1. 표지 (30초)

**화면:** 로고 + `Meerkit` + 한 줄 소개 "인증·사용자 관리를 갖춘 AI 서비스 스타터킷" + 이름, 날짜
**대본:**
> "안녕하세요, ○○○입니다. 오늘은 저희가 만들고 있는 **Meerkit**을 소개해 드리겠습니다. 오늘은 '무엇을, 왜 만드는지'와 '지금까지 만든 화면'을 보여 드리고, 다음 주에는 이 킷으로 실제 서비스를 세팅해 보여 드리겠습니다."

### 슬라이드 2. 문제 (1분)

**화면:** 제목 "새 서비스를 만들 때마다 이걸 또 만든다" + 체크리스트 아이콘 5개(회원가입 / 로그인 / 비밀번호 찾기 / 권한 / 관리자 화면)
**대본:**
> "AI 서비스를 만들려고 하면 정작 핵심 기능보다 먼저 만드는 게 있습니다. 회원가입, 로그인, 비밀번호 찾기, 사용자 권한, 관리자 화면입니다. 이건 서비스마다 거의 똑같은데 매번 처음부터 만들고, 만들 때마다 보안 실수의 위험도 같이 따라옵니다. 저희 프로젝트에서도 이 시간이 꽤 컸습니다."

> 발표 팁: "저희도 겪었다"는 한마디가 강사님과 수강생 모두에게 공감을 줍니다. 실제 겪은 경험이 있으면 한 문장 더하세요.

### 슬라이드 3. 해결: Meerkit (1분)

**화면:** 한 문장(0번 문장) + 웰컴 페이지 스크린샷
**대본:**
> "그래서 만든 것이 Meerkit입니다. 인증과 사용자 관리를 **미리 만들어 둔 스타터킷**이고, 개발자는 설정 파일 하나로 필요한 것만 켜서 씁니다. 개발자가 가져다 쓰는 **템플릿**이라서, 코드는 전부 프로젝트 안에 들어오고 마음대로 고칠 수 있습니다."

### 슬라이드 4. 누구를 위한 것인가 (45초)

**화면:** 사용자 3종 그림 — 서비스 개발자 / 서비스 관리자 / 서비스 사용자
**대본:**
> "사용자가 세 종류입니다. 킷을 가져다 쓰는 **개발자**, 그 서비스를 운영하는 **관리자**, 그리고 서비스를 쓰는 **일반 사용자**입니다. 일반 사용자는 가입하고 로그인하고, 관리자는 멤버를 보고 권한을 바꾸고, 개발자는 그 모든 것을 설정으로 조절합니다."

### 슬라이드 5. 범위: 넣은 것 / 뺀 것 (1분 15초) ★ 매니저 포인트

**화면:** 두 열 표

| 넣은 것 | 뺀 것 (의도적) |
| --- | --- |
| 회원가입·로그인, 비밀번호 재설정 | 소셜 로그인, 2단계 인증 |
| 역할 4종(MASTER/OWNER/VIEWER/WRITER) | 세부 권한(permission) 테이블 |
| 관리자: 멤버 검색·필터·역할 변경 | 사용량 기록·한도 관리 |
| 로그인 잠금, 약관 동의, 이메일 인증(선택) | 프로필 이미지 업로드 |

**대본:**
> "범위를 일부러 좁게 잡았습니다. 인증·권한·관리자 화면까지를 이번 목표로 하고, 소셜 로그인이나 사용량 관리는 **향후 확장**으로 미뤘습니다. 다 하려다가 아무것도 끝내지 못하는 것보다, 끝까지 쓸 수 있는 범위를 먼저 완성하는 쪽을 택했습니다."

> 매니저를 위한 한마디: "뺀 것을 말하는 것"이 계획이 구체적이라는 신호입니다.

### 슬라이드 6. 기획 과정 (1분 15초) ★ 강사님 포인트

**화면:** 타임라인 — 회의(화이트보드) → 테이블 설계 → 구조 설계 문서 → 프론트 구현. 가운데에 `users` ↔ `roles` 관계 그림
**대본:**
> "기획은 팀 회의에서 시작했습니다. 화이트보드에 회원 테이블과 권한을 그리고, 결정할 것을 정리했습니다. 핵심 결정이 세 가지입니다. 첫째, 로그인은 이메일이 아니라 **아이디**로 합니다. 둘째, 권한은 사용자 테이블에 이름을 직접 넣지 않고 **roles 테이블로 분리**합니다. 셋째, 탈퇴는 실제로 지우지 않고 **삭제 시각만 기록**하는 소프트 삭제로 합니다. 이렇게 정한 이유는 권한이 늘어도 사용자 테이블을 바꾸지 않아도 되고, 이력을 남길 수 있기 때문입니다."

### 슬라이드 7. 구조 (1분)

**화면:** 한 장짜리 그림
`브라우저(Next.js)` → `/api 프록시` → `FastAPI` → `PostgreSQL`
옆에 "킷 코드(src/meerkit) / 서비스 코드(app/(service))" 분리 표시
**대본:**
> "구조는 단순합니다. 브라우저 화면은 Next.js로 만들고, 같은 도메인의 프록시를 거쳐 FastAPI 서버와 PostgreSQL로 이어집니다. 중요한 것은 **킷 코드와 서비스 코드를 폴더로 나눈 것**입니다. 킷은 `meerkit` 폴더에만 있고, 개발자는 자기 서비스 코드를 따로 둡니다. 그래서 킷이 업데이트되어도 내 서비스가 깨지지 않습니다."

### 슬라이드 8. 설계 결정 세 가지 (1분 15초) ★ 강사님 포인트

**화면:** 카드 3장
1. 권한은 **서버가 최종 판단** (화면은 편의)
2. 액세스 토큰은 **메모리**, 리프레시 토큰은 **httpOnly 쿠키**
3. 설정은 **`meerkit.config.ts` 한 파일**
**대본:**
> "설계에서 지킨 원칙이 세 가지입니다. 하나, 화면에서 버튼을 숨기는 것만으로는 보호가 되지 않기 때문에 **권한은 항상 서버가 다시 검사**합니다. 둘, 토큰은 자바스크립트에서 훔쳐 가기 어렵게 액세스 토큰은 메모리에만, 리프레시 토큰은 읽을 수 없는 쿠키에 둡니다. 셋, 개발자가 코드를 뜯지 않고 **설정 파일 하나로** 로그인 잠금 횟수, 가입 항목, 테마를 바꾸게 했습니다."

### 슬라이드 11. 현재 진행 상황 (1분) ★ 매니저 포인트

**대본:**

**대본:**

## 말하기 요령 (발표 직전 체크)

- 슬라이드 한 장에 **메시지 하나**. 제목을 "~이다" 문장으로 쓰세요. 예: "인증은 매번 다시 만들 필요가 없다."
- **화면을 읽지 마세요.** 슬라이드에는 단어와 그림만, 문장은 입으로 말하세요.
- 숫자 세 개만 기억시키세요: **역할 4종 / 문서 32페이지 / 설정 파일 1개.**
- 데모 중에는 **말하고 누르지 말고, 누르고 나서 말하세요.** 화면이 바뀌는 동안 말이 겹치면 놓칩니다.
- 리허설은 **소리 내서 두 번**, 한 번은 시간을 재고 한 번은 데모 포함으로 하세요.
- 첫 30초와 마지막 30초는 **외워서** 말하세요. 시작과 끝이 단단하면 중간이 흔들려도 괜찮습니다.

## 2차 발표와 연결하기

1차 마지막에 던진 약속(가상 서비스 세팅)을 2차에서 그대로 증명합니다. 지금부터 정해 두면 좋은 것:

1. **가상 서비스 이름과 한 줄 소개** (예: "스터디 질문 답변 AI")
2. 그 서비스가 쓸 킷 기능 (로그인, 관리자 화면, 역할 중 무엇을 켜는지)
3. 2차 데모 전에 **백엔드 연동 + 한 줄 세팅**이 최소한 동작하는지

2차 슬라이드 첫 장은 "지난주 약속"으로 시작하고, 마지막은 "킷 없이 만들 때와 걸리는 시간 비교"로 끝내면 효과적입니다.
