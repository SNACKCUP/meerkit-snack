# 문서 사이트 분리 배포 (Meerkit 팀용)

> 대상: **Meerkit을 만드는 우리 팀**. 킷을 받아 쓰는 사용자용 설명이 아니다.
> 사용자용 배포 안내는 docs의 `Deployment` 페이지(`/docs/deployment`)에 있다.

## 배경

- 문서(`/docs`)는 킷 앱과 **따로 배포**한다. (킷 사용자 앱에 개발용 안내가 섞이지 않게, 문서만 고쳐도 앱을 다시 배포하지 않게)
- 현재는 같은 저장소의 같은 코드를 **환경 변수만 다르게** 두 번 배포하는 방식이다.

## 환경 변수

| 변수 | 킷 앱 | 문서 사이트 |
| --- | --- | --- |
| `NEXT_PUBLIC_SHOW_DOCS_PAGE` | `false` | `true` |
| `NEXT_PUBLIC_DOCS_ONLY` | `false` | `true` |
| `NEXT_PUBLIC_DOCS_URL` | 문서 사이트 주소 | - |

- `DOCS_ONLY=true`: 홈(`/`)이 `/docs`로 이동하고 `/me`, `/admin/members`는 404.
- 사용자용 문서에는 `DOCS_ONLY`를 **적지 않는다** (우리 팀 배포 전용 설정).
- `NEXT_PUBLIC_*`는 빌드 시점에 번들에 들어가므로 값을 바꾸면 다시 빌드한다.

## 확인 목록

- [ ] 킷 앱 환경에서 `/docs`가 404
- [ ] 문서 환경에서 `/me`, `/admin/members`가 404
- [ ] 웰컴 페이지 Docs 버튼이 문서 사이트를 **새 창**으로 연다
- [ ] 문서 사이트에는 `API_PROXY_TARGET`이 필요 없다 (미리보기는 목 데이터)

## 남은 결정

1. **완전 분리 여부**: `docs-site/` 독립 패키지로 옮길지.
   - 문서 미리보기가 킷 컴포넌트(`LoginForm`, `MemberTable` 등)를 import하므로, 분리하면 컴포넌트 공유 방식이 필요하다 (워크스페이스 패키지, 복사 동기화 등).
2. **생성물에 문서 포함 여부**: `create-meerkit`으로 만들어지는 프로젝트에 `/docs` 코드를 포함할지, 제외할지.
3. **검색 인덱스**: 지금은 브라우저에서 본문을 한 번 렌더링해 만든다. 문서가 커지면 빌드 시점에 JSON으로 미리 생성한다.
